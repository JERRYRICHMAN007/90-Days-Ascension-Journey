# AETHER OS V2 — MASTER USER JOURNEY ARCHITECTURE

**Classification:** Internal product experience specification  
**Status:** Binding user-journey doctrine  
**Sources of truth (only):**  
- `AETHER-OS-V2-MASTER-PRODUCT-VISION.md`  
- `AETHER-OS-V2-MASTER-INFORMATION-ARCHITECTURE.md`  
- `AETHER-OS-V2-MASTER-DOMAIN-ARCHITECTURE.md`  
- `AETHER-OS-V2-MASTER-DATA-MODEL.md`  
**Audience:** Founders, product, design research, coaching, AI leadership  
**Constraint:** User experience over time only. No UI. No code. No implementation. No visual design.

This document defines **how a human moves through Aether across minutes, days, weeks, seasons, years, and decades** — what the OS is trying to accomplish at each altitude, what must be true for success, and how the organism recovers from failure without betraying integrity.

**Primary object throughout:** Session of Becoming.  
**Feeling target (Vision §7):** Serious. Clear. Alive. Accountable. Free within structure.

---

# 0. Journey Laws

1. **Operate before configure.** Daily execution is the product; planning serves Sessions.  
2. **Season gates commitment.** No pretending the OS is “running” without an active Season (except read-only Remember during rest).  
3. **Evidence over narrative.** User stories must end in Session evidence, Reflection, or Archive — not vibes.  
4. **Shrink, don’t skip.** Recovery flows preserve non-negotiables at minimum faithful scope.  
5. **Identity over goals.** Journey stages may rename goals; they may not skip identity and Season truth.  
6. **Interconnection is lived.** Cross-domain interactions appear in daily and review journeys, not only in analytics.  
7. **AI coaches; humans execute.** AI proposes, cites, softens tone — never grants progress without evidence.  
8. **Legacy compounds.** Every stage should ask: *What does this leave for Year 10?*

## 1.1 First Launch

### User objective
Understand what Aether is, decide whether to commit, and enter the OS without drowning in configuration.

### System objective
Establish category clarity (Personal OS, not habit app), route to identity gate, and avoid premature object creation.

### Required inputs
- Public entry context (invite, organic, return visit)  
- Device/session integrity (conceptual auth readiness)

### Outputs
- Authenticated or deferred entry  
- Mental model: one life, Seasons, Domains, Sessions  
- No fake progress objects

### Decisions made
- Sign up / sign in / leave  
- Implicit persona signal (optional later in Settings)

### AI responsibilities
- Minimal or none pre-Season; if present, only orientation — no coaching without evidence base  
- Must not simulate progress

### Emotional state
Curiosity mixed with skepticism; fear of “another app that wastes time.” System must feel **serious and clear**, not gamified.

### Success criteria
User reaches Identity Gate with correct expectation: *Aether runs becoming with receipts.*

### Failure scenarios
- User expects infinite customization playground (Notion trap)  
- User expects motivation content feed  
- User bounces because “empty product” before Season Setup is explained

### Recovery flow
Re-entry messaging reinforces OS doctrine; route to Season Setup, not blank workspace. Empty states demand Season/Domain commitment (IA).

### Cross-domain interactions
None operational yet; narrative may preview organs as one organism (Vision WWDC story).

## 1.2 Onboarding

### User objective
Complete first-run commitment so tomorrow has executable Sessions, not a board of intentions.

### System objective
Commission first **Season** with identity, 3–5 Domains, non-negotiables, victory conditions, and seeded Systems — then land in Operate.

### Required inputs
- Authenticated User / Life  
- Persona hints (Beginner vs Operator vs Founder) for defaults only  
- Timezone / calendar truth (conceptual)

### Outputs
- `Season` in `active` (or `draft` → `active` in one flow)  
- `SeasonDomainActivation` records (primary/supporting/monitored)  
- `SeasonVictoryCondition`, `SeasonNonNegotiable`  
- Initial Journeys/Systems/DailyAction pipeline armed for Day 1  
- `IdentityProfile` draft or Season-bound identity statement

### Decisions made
- Which Domains are **primary** (expensive; Law of Minimum Domains)  
- Season duration and horizon (e.g., 6-month wedge)  
- Non-negotiables and shrink policy acknowledgment  
- Victory conditions (evidence-checkable)  
- Beginner: fewer Domains, smaller Sessions, guided protocols

### AI responsibilities
- Clarity Enforcer: resist activating all ten Domains  
- Propose starter Systems with cited templates (not user-specific evidence yet)  
- Explain shrink tiers for non-negotiables  
- No Mastery, no Life Score theater

### Emotional state
Hope + vulnerability; Beginners may feel shame about past failures — OS tone: **compassion with standard**, identity language (“becoming consistent”).

### Success criteria
Active Season exists; Home can present Day 1 Daily Actions → Sessions; user can articulate *who they are becoming this chapter* in one sentence.

### Failure scenarios
- Overconfiguration (Systems/Journeys/Goals spam)  
- All Domains primary  
- Victory conditions that are vibes-only  
- Skipping non-negotiable shrink definitions  
- Onboarding becomes settings tour

### Recovery flow
Strip to minimum Season: identity + 3 Domains + 1 System each + one victory condition each; defer advanced Steer. Resume onboarding checkpoint, not Operate with guilt.

### Cross-domain interactions
User selects organ set; system declares default coupling awareness (Body supports all; Knowledge→Projects→Brand pipeline explained if relevant Domains chosen).

## 1.3 Identity Creation

### User objective
Claim who they are becoming — player character language — not a list of goals.

### System objective
Create durable **IdentityProfile** and Season **identityStatement** aligned with Principle 3 (identity over goals).

### Required inputs
- Life container  
- Season draft or active Season  
- Optional persona default

### Outputs
- `IdentityProfile` (draft → active when earned or committed at Season start per policy)  
- Identity tags (Athlete, Builder, Writer, Operator, etc.)  
- Season identity statement as chapter contract

### Decisions made
- Core statement vs Season-specific statement  
- Which tags are active this Season  
- Whether identity upgrade requires Reflection (mid-Season) or allowed at Season commission

### AI responsibilities
- Help articulate identity language without granting “earned” upgrades without Reflection evidence  
- Detect goal-language masquerading as identity; redirect to Season identity framing

### Emotional state
Solemnity, possibility; some users feel fraudulence — normalize **becoming** vs **being**.

### Success criteria
Identity statement is actionable for Systems (can derive non-negotiables); tags map to selected Domains.

### Failure scenarios
- Goals pasted as identity (“lose 10 pounds” top)  
- Identity so vague it cannot drive Systems  
- Identity changes weekly without Reflection

### Recovery flow
Guided prompts tie identity to Systems (“what would a person like this do on a boring Tuesday?”); defer Goals until identity + Systems exist.

### Cross-domain interactions
Identity should name multi-domain self when multiple Domains primary (“shipping Comfort while rebuilding body”).

### Success criteria
Victory conditions are checkable; user can answer north-star question for this Season.

### Failure scenarios
- Vision board without Systems  
- Legacy fantasy without Projects/Session path

### Recovery flow
Collapse vision to one Season sentence + one Artifact/Project proof target + Body/Mind non-negotiables.

### Cross-domain interactions
Vision explicitly names couplings (e.g., ship + brand proof + body substrate).

## 1.5 Season Planning

### User objective
Design a **finite chapter** with beginning, end, and definition of “season won.”

### System objective
Steer-mode commissioning: Domains, Journeys, Projects, Systems, Goals, non-negotiables, shrink tiers, clarity budget.

### Required inputs
- Active or drafting Season  
- DomainMembership claims  
- Prior Season Archive (if any)  
- Analytics from previous Season (if any)

### Outputs
- Season plan graph: activations, Journeys, flagship Projects, Systems  
- WIP caps enforced conceptually  
- Season calendar truth (start/end)  
- Notification cadence for reviews

### Decisions made
- Primary vs supporting vs monitored Domains  
- Which Journeys are campaign-active  
- Flagship Projects count (few)  
- Mid-season amend rules if plan changes

### AI responsibilities
- Evidence-based planning if prior Season exists (cite Analytics)  
- Clarity Enforcer on WIP and Domain count  
- Propose interconnection risks (“training + ship + brand cadence may overload”)  
- AIProposal for System changes — user accepts in Steer

### Emotional state
Strategic calm (Vision §7); healthy tension — excitement bounded by finite Season.

### Success criteria
Season `active` with evidence-checkable victory conditions; Day 1 Daily Actions generatable.

### Failure scenarios
- Infinite Season  
- Plan rebuild addiction instead of execution  
- No shrink tiers on non-negotiables  
- Ten Domains at full load

### Recovery flow
Season amend flow with explicit recommit; pause Domains; shrink Systems; never delete miss history.

### Cross-domain interactions
Season planning is organism planning: conflict resolution order (non-negotiables, Body/Mind mins, Relationships, Spirit sacred constraints, then Career/Projects/Brand).

## 1.6 Daily Planning

### User objective
Know what matters **today** without rebuilding the whole life.

### System objective
Translate Systems → **DailyActions** for the date; rank Operate queue: Now > Next > Later; apply Season context pulse only.

### Required inputs
- Active Season  
- SeasonDomainActivation (primary/supporting)  
- Active Systems, Journeys, Projects  
- Calendar truth / energy signals (user or inferred)  
- Prior day Reflection (optional)

### Outputs
- Dated DailyActions  
- Session candidates with done-definitions and shrink tiers  
- Deferred/Later queue (demoted)  
- Optional minimum faithful set under load

### Decisions made
- Which Session is **Now**  
- Whether to shrink tier vs defer (defer ≠ complete)  
- Whether to accept Coach priority proposal

### AI responsibilities
- Home-level: suggest Now, shrink set, interconnection caution (cited if pattern exists)  
- No calendar packing as destiny (anti-Motion)  
- Fight backlog takeover

### Emotional state
Grounded, not frantic; sharp focus during execution window.

### Success criteria
User can start Now Session without opening deep Steer tree; daily plan fits clarity budget.

### Failure scenarios
- Daily planning becomes hour-long re-plan  
- Later list outshouts Now  
- Scheduling mistaken for completion  
- Cross-domain mush into one vague “life session”

### Recovery flow
Force Operate path: pick one non-negotiable shrink Session; defer rest with honesty; evening Reflection captures overload cause → weekly System tune.

### Cross-domain interactions
Today’s Sessions span Domains on Home; Body readiness may reorder or shrink Projects/Career Sessions; interconnection flags surface lightly.

## 1.7 Session Execution

### User objective
Execute one bounded unit of becoming with clear done and honest evidence.

### System objective
Run Session lifecycle: Ready → Active → Complete (or Missed/Deferred); capture SessionEvidence; update DailyAction; feed Analytics pipeline.

### Required inputs
- Session with provenance (System, Domain, Season)  
- Done-definition and optional ShrinkTier  
- User presence and integrity

### Outputs
- `Session` terminal state  
- `SessionEvidence` (+ specialized payloads: Workout, ReadingSession, etc.)  
- Optional SessionAnnotation  
- Optional Session-altitude Reflection  
- Analytics input events; AI memory update

### Decisions made
- Full vs shrink tier  
- Manual complete vs abandon vs defer  
- Honesty in annotation

### AI responsibilities
- Session Ready: clarify done-definition, minimum faithful scope  
- Session Complete: prompt honest annotation, not inflation  
- Integrity Sentinel on suspicious patterns (cultural, not punitive dark patterns)  
- Never auto-complete

### Emotional state
During Active: sharp focus, protected from backlog noise. After honest complete: quiet pride. After miss: safe honesty without identity collapse.

### Success criteria
Completed Sessions have evidence; non-negotiables either completed at valid shrink or honestly missed with Reflection path.

### Failure scenarios
- Clock-complete  
- Task-check without Session evidence  
- Heroic intensity destroying next week  
- Fake manual complete without cultural honesty

### Recovery flow
Miss → annotate → shrink tomorrow → System tune at weekly review; no rewrite of history; InterconnectionSignal if pattern.

### Cross-domain interactions
Single primary Domain per Session; miss in Body may emit risk to Mind/Career/Projects; Brand Session may consume Projects Artifact eligibility.

## 1.8 Reflection

### User objective
Convert execution into learning; adjust Systems without shame spiral or plan cosplay.

### System objective
Close feedback loop at correct altitude: Session, Daily, Weekly, Journey, Season, Legacy.

### Required inputs
- Session outcomes (complete/miss/defer)  
- Analytics context where relevant  
- Emotional annotations (non-scoring)

### Outputs
- `Reflection` records  
- Principle candidates  
- Adaptation proposals (human or AIProposal)  
- Identity review (only if earned)  
- Inputs to next Daily/Weekly/Season Steer

### Decisions made
- What failed: system vs circumstance  
- Whether to propose System change  
- Whether identity language upgrade is justified

### AI responsibilities
- Reflection Facilitator with evidence-backed questions  
- Cite completion rate vs feeling (“I feel behind”)  
- Propose System adaptations with citations  
- No therapy replacement claims

### Emotional state
Metacognitive awareness; compassion + standard; humility.

### Success criteria
Reflection cites Sessions; produces at least one actionable System insight or honest acceptance of variance; Season Reflection completed before archive seal.

### Failure scenarios
- Reflection without execution (therapy cosplay)  
- Reflection that marks Sessions complete  
- Endless journaling (Journal entity demoted — not primary)  
- Identity upgrade without evidence

### Recovery flow
If user avoids Reflection: shorten guided form; tie to weekly non-negotiable; Coach cites pattern of unexamined misses.

### Cross-domain interactions
Weekly/Season Reflection evaluates organism couplings; zombie consistency detection across Domains.

Steer the week: tune Systems, protect boundaries, prepare next week’s faithfulness.

### System objective
Steer altitude review combining Analytics pulse + Weekly Reflection; adaptation queue; interconnection check.

### Required inputs
- Week’s Sessions + Reflections  
- Domain Analytics snapshots  
- Season non-negotiables and victory progress  
- InterconnectionSignals open

### Outputs
- Weekly Reflection (required cadence)  
- Accepted AIProposals / System version changes  
- Next week clarity: WIP, priorities

### Decisions made
- System tune vs hold course (evidence-based improvement)  
- Domain pause/amend (expensive)  
- Shrink vs intensity change

### AI responsibilities
- Cite week evidence; flag self-erasure (Founder), metric anxiety (Brand), tutorial hell (Knowledge)  
- Recommend shrink-not-skip  
- Interconnection Guardian summary

### Emotional state
Strategic calm; reduced locus of illusion; facing mirror worth trusting.

### Success criteria
Weekly Reflection completed; at least one Steer action OR explicit “hold course” with evidence; non-negotiable integrity visible.

### Failure scenarios
- Weekly review skipped repeatedly  
- Rebuild entire plan instead of tune Systems  
- Ignore interconnection signals  
- Shame-based motivation spikes

### Recovery flow
Minimum weekly: 10-minute evidence review + one System knob; Coach escalates gently; shrink Operate load until review restored.

### Cross-domain interactions
Full row of Domain health; e.g., training slip + writing drop correlated → tune one System in each or shrink Brand cadence.

# 2. Nested Lifecycles

## 2.1 Daily lifecycle

```text
Wake → (optional Mind/Spirit/B Body non-negotiable ordering per Season)
  → Enter OS Shell / Operate / Home
  → Season identity pulse (context only)
  → DailyActions materialized for calendar date
  → Select Now Session → Ready → Active → Complete (+ evidence)
  → Optional Session Reflection
  → Next Session loop OR honest defer/miss handling
  → Cross-domain Sessions continue until minimum faithful set met or day closed
  → Evening: Daily Reflection (integrity of day)
  → Shutdown ritual (Mind System optional)
  → Sleep
```

**System invariant:** Operate path shallow; Steer not required for a good day.  
**Evidence invariant:** No day “won” by date rollover.  
**Ranking:** Now > Next > Later.

---

## 2.2 Weekly lifecycle

```text
Mon–Sun: Daily lifecycle × N
  → Weekly Review window (Steer + Understand)
  → Weekly Reflection (required)
  → System adaptations applied (AdaptationApplication)
  → Interconnection check
  → Next week DailyAction generation rules updated
  → Notifications cleared/scheduled for next week
```

**Cadence:** Same weekday anchor preferred (ritual gravity).  
**Beginner:** shorter review; **Founder:** boundary audit emphasis.

---

## 2.3 Monthly lifecycle

```text
Weeks 1–4(5): Weekly lifecycle
  → Monthly block review (Understand + Steer)
  → Project/Journey audit (finish / abandon / shrink)
  → Wealth review Session if Domain active
  → Relationship health Reflection if active
  → Mid-Season amend optional
  → Analytics snapshot for month
```

**Clarity:** Monthly is not a second daily planning session.

---

## 2.4 Seasonal lifecycle

```text
Season Planning (commission) → active Season
  → Daily/Weekly/Monthly loops
  → Mid-season review (optional checkpoint)
  → Season closing window
  → Seasonal Review + Reflection
  → Victory evaluation
  → MasteryDelta + LegacyRecord seal
  → Legacy Domain curation
  → Rest OR new Season Planning
```

**Duration:** Finite (e.g., 6-month wedge); victory conditions explicit.  
**Archive:** Default retain.

---

## 2.5 Annual lifecycle

```text
Multiple Seasons (1–4 per year typical)
  → Annual Review (Life altitude)
  → Identity supersession optional (earned)
  → Legacy vault year spotlight
  → Theme selection for upcoming Seasons (not identity wipe)
  → Domain emphasis for next year
```

**Anti-pattern:** January reset gimmick.

---

## 2.6 Lifetime lifecycle

```text
First Launch → Onboarding → Season 1…N
  → Multi-year Mastery compounding
  → Legacy Building continuous (thin → rich)
  → Optional rest years
  → Decade reviews
  → Life record as autobiography of execution
  → Account integrity / export / ethical end states
```

**Retention thesis:** Leaving means abandoning continuous record of becoming (meaning lock-in, not spite).

# 3. Edge Cases

## 3.1 User misses 30 days

### Situation
No Sessions (or only sporadic) for ~30 days; guilt, identity threat, temptation to delete history or “start fresh.”

### System response
- Do **not** auto-complete or reset Mastery/identity.  
- Enter **re-entry mode**: read-only Legacy optional + single Season recommission or continue Season with amend.  
- Coach cites actual completion rate vs feeling; no shame storms.  
- Shrink all Systems to **minimum faithful** non-negotiables (1–3 Sessions/day max).  
- Law of Shrink: non-negotiables shrink, not vanish.  
- Weekly Review mandatory lightweight.  
- Interconnection: expect Body/Mind/Projects decay signals — use to prioritize substrate Sessions.

### Recovery flow
1. Honest Season or mid-Season Reflection (30-day gap narrative).  
2. Accept AIProposal to shrink Systems.  
3. 7-day “return integrity” goal: complete shrink Sessions only.  
4. Expand only after week evidence.  
5. No backdated fake Sessions.

### Success criteria
User returns to Operate without configuration loop; miss history preserved.

---

## 3.2 User gets injured

### Situation
Body Domain compromised; training Systems break; fear of losing entire Season.

### System response
- Body Journey/Project amend: rehab Journey, recovery Systems first-class.  
- Predefined shrink/replacement tiers on Body System before heroics.  
- Interconnection signals to Projects/Career: reduce deep-work expectations with citation.  
- Deload/rehab ≠ failure in Analytics narrative.  
- Season victory conditions may be **waived_with_reflection** for body-specific targets if alternate evidence defined.  
- Mind/Spirit/Relationships Sessions may increase relatively — still single-Domain Sessions.

### Recovery flow
1. Body System version change (AdaptationApplication) with medical/user constraint note in Reflection.  
2. Shrink non-negotiables to rehab minimum.  
3. Weekly review tracks readiness proxy, not vanity metrics.  
4. Re-ramp protocol after evidence window.

### Cross-domain
Career/Projects shrink; Brand cadence may reduce; Knowledge/Spirit may support mental game and meaning.

---

## 3.3 User changes goals

### Situation
Mid-Season new ambitions; old Goals feel wrong.

### System response
- Goals are mid-stack — change allowed via Steer with Reflection, not silent.  
- Identity/Season identity outrank Goals; if goals change, check identity statement still true.  
- Retire Goals honestly (`missed` / `retired`); no delete to hide.  
- WIP cap: new Goals require finish/drop of others.  
- AI cites intention inflation if goals multiply without Sessions.

### Recovery flow
1. Weekly or ad-hoc Reflection: why change (evidence vs whim).  
2. Season amend if victory conditions affected.  
3. Update Systems, not just Goals.  
4. Resume Operate.

---

## 3.4 User changes career

### Situation
New job, layoff, founder pivot; Career Domain chaos.

### System response
- Season amend likely required.  
- Career Projects/Journeys archive or abandon honestly.  
- Wealth runway signals if Domain active.  
- Boundary Systems reset for new role.  
- Founder persona: flag self-erasure patterns.  
- Projects/Brand may pivot with new flagship Project.  
- Legacy: chapter narrative includes vocation change with evidence.

### Recovery flow
1. Career Reflection + Season amend.  
2. Reduce Domains in play temporarily if needed (3 max primary).  
3. Non-negotiable Body/Mind/Relationship protections enforced.  
4. 90-day recommit Season optional template.

---

## 3.5 User loses motivation

### Situation
Low affect; “what’s the point”; temptation to abandon OS.

### System response
- Motivation is downstream of Systems (Vision).  
- Offer **smaller faithful Sessions**, not abandonment or shame.  
- Mind annotations welcome; emotion does not complete Sessions.  
- Coach softens tone; cites prior consistency evidence if exists.  
- Spirit/Legacy orientation optional prompts (meaning, not hype).  
- No engagement notifications baiting return.  
- Shrink Operate surface to one Now Session.

### Recovery flow
1. Complete one shrink Session (any non-negotiable).  
2. Session Reflection optional micro.  
3. Repeat 3 days before Steer planning.  
4. Weekly Review examines System size vs life load.

### Anti-patterns forbidden
Guilt storms, streak loss theatrics, fake XP for opening app.

---

## 3.6 User completes a season

### Situation
Victory conditions met or honestly evaluated; natural end of horizon.

### System response
- Mandatory Seasonal Review pipeline (§1.11).  
- Archive seal; MasteryDelta; Achievement markers if evidence-backed.  
- Celebrate quietly — integrity, not confetti-as-product.  
- Recommend **rest** inter-season (Life rest mode).  
- Legacy Domain curation Sessions.  
- Do not auto-start next Season without commission.

### Recovery flow
N/A — success path. Optional: inter-season read-only Remember, light Spirit/Relationship focus, no Operate pressure.

---

## 3.7 User starts a new season

### Situation
After rest or immediately (user choice); new chapter.

### System response
- Full Season Planning (§1.5) — not clone of old Season blindly.  
- Read prior LegacyRecord + Analytics for evidence-based planning.  
- Domain activation expensive; carry forward Principles.  
- Identity: new Season statement; Life Identity supersession only if earned.  
- Beginner vs Year-5 user: same graph, different depth defaults.

### Recovery flow
If user skips planning: block Operate until minimum Season commission (identity + 3 Domains + Systems + victory conditions).

# 4. Ideal Aether Day

An **Ideal Aether Day** is not a maximal day. It is a **faithful day**: identity-aligned Sessions executed with evidence, reflection closed, tomorrow honestly seeded — across whichever Domains the Season activated.

## 4.1 Principles of the ideal day

- One **Now** at a time.  
- Non-negotiables completed at full or valid shrink tier.  
- No calendar-complete fiction.  
- Evening closes the loop.  
- Body supports Mind; Mind protects focus; Spirit/Relationships optional but protected if Season declares.  
- Steer is minimal; Operate is the spine.

## 4.2 Timeline (logical, not UI)

### Phase A — Wake to OS entry (0–30 min typical)

**User:** Transition from sleep to intentional day; optional Body/Mind/Spirit morning Systems (Season-defined).  
**System:** May surface non-negotiable Session window notifications (priority lane Operate); no engagement bait.  
**Cross-domain:** Body readiness influences suggested shrink for later Career/Projects Sessions (signal only until pattern exists).

### Phase B — Morning Operate block (primary execution)

**User:** Enter OS Shell → Home → Season pulse (who I am this chapter).  
**System:** Present Today Sessions rail; rank Now > Next > Later; hide backlog noise.  
**Execution loop:**  
1. Now Session Ready — confirm done-definition / shrink tier.  
2. Active — protected execution.  
3. Complete — SessionEvidence captured.  
4. Optional Session Reflection (30–90 sec if System requires).  
5. Return Home; next Now.

**Typical Domain order (Season-dependent, not global law):**  
- Body non-negotiable early (energy substrate).  
- Mind clarity ritual if System active (short).  
- Knowledge intake Session if scheduled (feeds later Projects).  
- Career deep-work Session OR Projects build Session (not both as Now simultaneously — sequential Sessions).  
- Brand distribution Session if cadence day (Artifact pipeline check).

**AI:** Clarify done-definition; interconnection caution only if cited pattern; no chat detour.

**Emotional target:** Grounded, sharp, accountable.

### Phase C — Midday (life happens)

**User:** Career meetings, life interruptions, energy dip.  
**System:** Defer ≠ complete; missed Sessions honest; shrink proposal if overload detected.  
**Cross-domain:** Career colonization triggers Relationship/Body risk signals after aggregated misses — not instant nag.

### Phase D — Afternoon Operate (second wind or shrink day)

**User:** Resume next Sessions or execute **minimum faithful set** only.  
**System:** If chaos flag: offer minimum faithful set (predefined shrink tiers).  
**Projects/Brand:** Prefer one faithful ship/publish shrink over zero heroics.

### Phase E — Evening close (15–30 min)

**User:** Complete remaining non-negotiable shrink Sessions OR honestly miss with annotation.  
**System:** Daily Reflection prompt — day integrity, energy, tomorrow shrink/adapt.  
**Relationships:** Presence Session if Season non-negotiable (often evening).  
**Wealth/Spirit:** Only if Systems schedule (e.g., weekly money review on specific day, not daily default).

**Outputs:** Daily Reflection; Principle candidate optional; tomorrow DailyActions preview logic updated.

**Emotional target:** Quiet pride if honest; safe honesty if miss; no identity collapse.

### Phase F — Sleep prep

**User:** Mind shutdown ritual if System exists; devices/attention hygiene as Habit under System.  
**System:** No notifications except critical integrity (rare overnight).  
**Legacy:** No Operate pressure; optional gratitude/orientation note → Reflection attachment, not scoring.
